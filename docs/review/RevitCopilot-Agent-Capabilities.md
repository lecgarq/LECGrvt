# Revit Copilot: agent capabilities and reuse

Target: Revit 2026; add-in `net10.0-windows`, MCP server `net10.0`. Source root: `C:\LECG\RevitAddins\LECG\RevitCopilot`.

## Available operations

The 16 MCP entrypoints retain the original six tools and add compact discovery/execution/recipe/batch tools. Search `agent_capabilities` for hand-written contracts and `api_search` for the 2,216 bound accessor functions; do not put the full catalogs into every prompt. [Current API expansion and evidence](RevitCopilot-API-Expansion.md).

The original table contains 18 reads and 16 changes. `elements_find` adds a bounded runtime-type-aware element query, and `workflow_change_batch` adds atomic multi-step execution. Rename supports types, views, sheets, levels, grids and materials. Material assignment requires a writable material parameter, not an arbitrary parameter. Slab offset currently supports floors; shape reset supports floors and toposolids. Existing production rename, material-graphics, offset and shape-reset services are source-linked rather than regenerated by the agent.

## Safe changes

New change operations use `agent_preview`, then `agent_apply`. Preview starts a real Revit transaction, computes the result and rolls it back. Apply requires a one-use token valid for 10 minutes, the same document, no intervening document revision, and an explicit local Yes/No confirmation. Apply starts its own transaction and commits only on success; failures roll back the batch. Preview-created IDs are provisional: use committed results when resolving later steps.

Targets are explicit, with at most 50 elements per change. Deletion reports dependent deletions and rejects a cascade above 200 elements. The default local confirmation is No. This enforced preview flow applies to the new agent operations; the original legacy tools retain their existing behavior.

## Recipes without history dumping

Eight curated starter templates cover model overview, wall audit, type renaming, material graphics, sheet audit, reviewed cleanup, slab elevation and parameter batches. They are templates, not claims of successful execution in the current project.

Use `agent_recipe_save` with 1–8 successful receipt IDs from the current session. Revit asks the user to confirm the results. The saved recipe replaces every argument value with a fresh-input placeholder; it does not persist old element IDs as reusable targets. A recipe records successful execution plus user review, not automatic proof of every design requirement.

Storage: `%LOCALAPPDATA%\RevitCopilot\recipes\workflows.json`. Up to 100 saved recipes; keyword search returns at most five summaries. Fetch an individual recipe only when relevant. Atomic batches now preserve operation structure and symbolic dependencies when saved; literal arguments still become fresh-input placeholders. There is no arbitrary code execution, automatic self-training, or unattended recipe runner.

Example messages in the Revit panel:

- “Find tools for renaming wall types. Inspect the current selection and preview adding the prefix LECG_. Do not apply yet.”
- “Save the successful steps we just confirmed as a reusable recipe called Wall type naming.”
- “Find my Wall type naming recipe and prepare it for the current selection with fresh inputs. Show the preview first.”

## Quota protection

Catalog discovery and recipe lookup run locally without AI or embedding calls. Read lists default to ten rows, capped at 50, with pagination. Parameter requests select named fields instead of dumping every parameter. Normal conversational reasoning and tool coordination still consume quota. No paid API fallback or additional model training is introduced by this layer.

Not implemented: the complete Revit API, automatic unused-content purge, render-asset synchronization, autonomous code generation, or automatic learning from all previous conversations. Add future functions as bounded C# operations with validation and tests.

## Build and install

From `C:\LECG\RevitAddins\LECG\RevitCopilot`, use `dotnet build -c Release -p:SkipRevitDeploy=true` to build without touching the live installation. With Revit closed, `dotnet build -c Release` installs the add-in and bundled MCP server. From its `McpServer` subdirectory, `dotnet build -c Release` also updates the separate legacy MCP installation used by existing desktop registrations. Reopen Revit after installation; reconnect existing MCP clients if their tool catalog is cached.
