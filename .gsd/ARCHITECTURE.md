## Components

### Core Integration (`App.cs`)
- **Purpose:** Entry point for Revit. Initializes the DI container and the Ribbon UI.
- **Location:** `src/App.cs`
- **Responsibilities:** Assembly resolution for DI version conflicts, Bootstrapper invocation.

### Dependency Injection (`Bootstrapper.cs` & `ServiceLocator.cs`)
- **Purpose:** Manages object lifecycles and provides access to services.
- **Location:** `src/Core/`
- **Pattern:** Uses `Microsoft.Extensions.DependencyInjection`. `ServiceLocator` provides static access for Revit's parameterless command instantiation.

### Command Infrastructure (`RevitCommand.cs`)
- **Purpose:** Base class for all Revit commands.
- **Location:** `src/Core/RevitCommand.cs`
- **Features:** Automated transaction management, exception handling, and logger initialization.

### Service Layer (`src/Services/`)
- **Purpose:** Encapsulates all business logic and Revit API calls.
- **Location:** `src/Services/`
- **Characteristics:** Interface-based design, registered as Singletons. Highly granular (130+ files).

### View/ViewModel (`src/Views/` & `src/ViewModels/`)
- **Purpose:** Presentation logic and UI.
- **Location:** `src/Views/`, `src/ViewModels/`
- **Stack:** WPF and CommunityToolkit.Mvvm for source-generated properties and commands.

## Data Flow

1. **User Interaction:** User clicks a ribbon button.
2. **Command Activation:** Revit instantiates a `RevitCommand`.
3. **Orchestration:** The command loads settings via `SettingsManager`, shows a WPF dialog (`View` + `ViewModel`).
4. **Execution:** On confirmation, the command resolves necessary services from the `ServiceLocator`.
5. **Logic:** Services perform Revit API operations (transactions, geometry processing, etc.), reporting progress via callbacks.
6. **Logging:** Progress and errors are captured by `Logger` and displayed in `LogView`.
