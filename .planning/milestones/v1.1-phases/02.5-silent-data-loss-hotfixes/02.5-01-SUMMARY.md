## Sentinel Rationale for "Text Orientation"

"Text Orientation" has no `BuiltInParameter` in Revit 2024. Two choices:
1. Use `LookupParameter("Text Orientation")` — locale-fragile (returns null on Spanish)
2. Sentinel fallback — safe-by-default per CONTEXT.md §A ("treat unreadable parameters as distinct")

`GetOrientationSentinel` implements both: tries `LookupParameter` first (preserves English behavior — regression safe), then returns `$"ORIENTATION_UNREADABLE:{type.Id}"` when the parameter is unreadable. The `type.Id` embed ensures two distinct types with unreadable orientation always produce different signature parts and are never falsely merged.

## Decisions Made

- Used `BuiltInParameter.TEXT_ALIGNMENT` not `TEXT_ALIGN_HORZ` — critical distinction: TEXT_ALIGN_HORZ is instance-level (on TextNote instances), would return null when called on a TextNoteType
- Orientation sentinel tries LookupParameter first — preserves English-locale integer value for existing legitimate merges (regression-safe)
- Removed `GetIntParamByName` and `GetElementIdParamByName` — had zero callers after replacement; leaving dead locale-fragile code in place would invite reuse
