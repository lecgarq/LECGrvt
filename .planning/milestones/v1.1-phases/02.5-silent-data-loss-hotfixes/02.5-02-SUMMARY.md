**Pre-flight two-pass gate in SwapInstances logs every unsupported instance ([UNSUPPORTED]) then aborts the entire batch ([REFUSED] + InvalidOperationException) instead of silently skipping with [SKIP] and reporting [SUCCESS]**

## Two-Pass Shape Rationale

The plan mandates all-or-nothing semantics per CONTEXT.md §A. Achieving this inside a single transaction requires:

1. **Pass 1 (scan, no mutation):** iterate all instances, collect unsupported ones, log each with element ID and reason. Does not call `newSymbol.Activate()` or `doc.Create.*` — no side effects yet.
2. **After Pass 1:** if any unsupported instance was found, log `[REFUSED]` and throw `InvalidOperationException`. `TransactionService.RunInternal` catches and re-throws after `Transaction.RollBack`, so no DB changes survive.
3. **Pass 2 (mutate, only if Pass 1 clean):** original swap loop — activate symbol, place new instance, rotate, delete old.

This is the pattern recommended in RESEARCH.md ("Primary recommendation — refuse-all, single transaction"). It avoids `SubTransaction` complexity and ensures the Revit project is never left in a half-migrated state.

## Why Hosted/Face-Hosted/Curve Types Are Refused (Deferred to v1.2)

| Location type | Why refused now | v1.2 plan |
|---|---|---|
| `LocationCurve` | Requires `doc.Create.NewFamilyInstance(curve, symbol, ...)` overload; different placement API; needs separate test fixture | Phase v1.2 curve-support milestone |
| `Host != null` (wall/floor hosted) | Requires host-aware placement overload `NewFamilyInstance(pos, symbol, host, face, ...)` | Phase v1.2 hosted-instance milestone |
| `HostFace != null` (face hosted) | Requires `NewFamilyInstance(face, symbol, reference, ...)` overload; face reference is not trivially reconstructible post-delete | Phase v1.2 face-hosted milestone |

Adding placement paths for these three types in this hotfix phase would violate CONTEXT.md scope boundary and introduce untested code paths. Refusing is strictly safer.

## Decisions Made

- **Refuse-all over partial-success:** CONTEXT.md §A explicitly mandates this; partial migration is the bug being fixed, so any partial-success path would reintroduce it.
- **GetUnsupportedReason check order:** LocationCurve before HostFace before Host — a face-hosted instance may have both `Host` and `HostFace` set; HostFace first gives the more precise label. A wall-hosted door has `Location is LocationPoint && Host != null`; checking Host after HostFace correctly catches it (RESEARCH.md Pitfall 1).
- **No SubTransaction:** keeps complexity minimal; a single rollback on InvalidOperationException is sufficient and is already tested by the existing `IsExpectedCategoryChangerException` catch.
- **No TaskDialog:** CONTEXT.md §A locks the logging surface to LogView only — consistent with all other commands in this codebase.
